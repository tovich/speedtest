# Speedtest — свой сервер для проверки скорости интернета

Один контейнер на Go (~15 МБ) со страницей без фреймворков. Показывает посетителю его IP,
страну, город и провайдера (ASN) и измеряет параметры соединения до этого сервера.

## Что измеряется

| Параметр | Как меряется |
|---|---|
| Загрузка, средняя и пиковая | 6 параллельных HTTP-потоков несжимаемых данных, 10 с; первые 1,5 с (разгон TCP) не учитываются ни в средней, ни в пиковой; пиковая — лучшая секунда |
| Отдача, средняя и пиковая | 4 параллельных POST-потока по 8 МБ случайных данных, 10 с |
| Пинг в покое: медиана, мин, ср, макс | 20 эхо-сообщений по WebSocket |
| Джиттер и σ | средняя разница соседних замеров пинга и их стандартное отклонение |
| Задержка под нагрузкой ↓ и ↑ | медиана пинга по WebSocket, который отправляется каждые 200 мс во время загрузки и отдачи |
| Bufferbloat, A+…F | на сколько задержка под нагрузкой выше, чем в покое: < 5 мс — A+, < 30 — A, < 60 — B, < 200 — C, < 400 — D, больше — F |
| Потери пакетов, задержка и джиттер UDP | 200 пакетов с интервалом 12 мс через WebRTC DataChannel без повторной отправки (`maxRetransmits: 0`); пакет, не вернувшийся за 1 с, считается потерянным |
| Время до первого байта | от отправки запроса загрузки до получения заголовков ответа, медиана |
| Протокол, IPv4/IPv6, объём данных, длительность теста | — |
| Пригодность для стриминга, игр и видеозвонков | оценка от «Плохо» до «Отлично» по совокупности метрик |

История последних 30 тестов хранится только в браузере посетителя.

## Как проходит тест

Тест идёт около 26 секунд, четыре этапа отображаются под спидометром:

1. **Пинг** (~2 с) — столбик на каждый замер и линия медианы.
2. **Потери** (~3,5 с) — сетка из 200 ячеек, по одной на пакет: зелёная — пакет вернулся, красная — потерян.
3. **Загрузка** (10 с) и 4. **Отдача** (10 с) — спидометр и график скорости; на графике точками — пинг под нагрузкой.

Итоги остаются в карточках «Подробно», «Чего ждать от соединения» и в истории;
кнопка «Скопировать результат» копирует их текстом.

## Установка одной командой

На любом Linux-сервере amd64 или arm64. Docker установится сам, если его нет.

```bash
curl -fsSL https://raw.githubusercontent.com/tovich/speedtest/main/install.sh | sudo bash
```

Страница откроется на `http://<сервер>:8080`. Параметры передаются после `bash -s --`:

```bash
# свой домен с HTTPS (Caddy, сертификат Let's Encrypt; порты 80 и 443 должны быть свободны)
curl -fsSL https://raw.githubusercontent.com/tovich/speedtest/main/install.sh | sudo bash -s -- --domain speed.example.com

# за Nginx Proxy Manager: подключиться к его docker-сети (см. раздел ниже)
curl -fsSL https://raw.githubusercontent.com/tovich/speedtest/main/install.sh | sudo bash -s -- --proxy-network nginx-proxy_default

# название и город сервера
curl -fsSL https://raw.githubusercontent.com/tovich/speedtest/main/install.sh | sudo bash -s -- --name "Speedtest Москва" --location Москва
```

| Параметр | Что делает |
|---|---|
| `--domain ДОМЕН` | HTTPS через встроенный Caddy |
| `--proxy-network СЕТЬ` | подключить к docker-сети своего прокси; HTTP-порт наружу не публикуется |
| `--behind-proxy` | сервис за прокси, который не в Docker: IP посетителя брать из `X-Forwarded-For` |
| `--direct` | отменить режимы домена и прокси, вернуться к прямому доступу по порту |
| `--port`, `--udp-port` | HTTP-порт (8080) и UDP-порт теста потерь (3479) |
| `--name`, `--location` | название в шапке и город сервера |
| `--public-ip IP` | внешний IP для UDP-теста, если сервер за NAT |
| `--no-city` | GeoIP только по странам (базы ~20 МБ вместо ~135 МБ) |
| `--uninstall` | удалить сервис вместе с данными |

Сервис ставится в `/opt/speedtest` (другой каталог — переменная `SPEEDTEST_DIR`), настройки
лежат в `/opt/speedtest/.env`. Повторный запуск той же команды обновляет сервис до свежей
версии и сохраняет настройки. Установщик открывает нужные порты в ufw или firewalld, если они включены.

Образ `ghcr.io/tovich/speedtest` собирает GitHub Actions при каждом коммите в `main`.

## Публикация через Nginx Proxy Manager

1. Установите с `--proxy-network <сеть NPM>`. Имя сети:
   `docker inspect <контейнер NPM> -f '{{range $k,$v := .NetworkSettings.Networks}}{{$k}} {{end}}'`.
   Если NPM уже запущен, установщик сам подскажет нужный параметр.
2. В NPM создайте Proxy Host:
   - **Details:** scheme `http`, Forward Hostname `speedtest`, Forward Port `8080`;
     **Websockets Support** — включить; **Cache Assets** — выключить.
   - **SSL:** сертификат Let's Encrypt, Force SSL; **HTTP/2 Support — выключить**.
   - **Advanced:**
     ```nginx
     proxy_buffering          off;
     proxy_request_buffering  off;
     client_max_body_size     0;
     client_body_buffer_size  1m;
     gzip                     off;
     ```
3. UDP-порт 3479 идёт мимо NPM напрямую в контейнер. Если сервер за роутером, пробросьте его.

С HTTP/2 браузер пускает все потоки теста через одно TCP-соединение, и на реальных каналах
(с задержкой и потерями) скорость получается заметно ниже настоящей — как у одного потока.
По HTTP/1.1 браузер открывает несколько отдельных соединений, как и другие тесты скорости.
Без `client_max_body_size 0` nginx отклоняет отдачу ошибкой 413. Без WebSocket не будет пинга
и задержки под нагрузкой. С буферизацией тест измеряет скорость до nginx, а не до посетителя.

Для обычного nginx нужны те же директивы и проксирование WebSocket на `/api/ws`.
Если перед сервером включён прокси Cloudflare (оранжевое облако), тест будет мерить
скорость до Cloudflare, а UDP не пройдёт — для этого домена оставьте только DNS.

## Настройки (`.env`)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `HTTP_PORT` | `8080` | порт страницы на сервере |
| `RTC_UDP_PORT` | `3479` | UDP-порт теста потерь пакетов; должен быть открыт снаружи |
| `SERVER_NAME` | `Speedtest` | название в шапке и во вкладке браузера |
| `SERVER_LOCATION` | — | город сервера, показывается в карточке «Сервер» |
| `RTC_PUBLIC_IP` | — | внешний IP для UDP-теста; по умолчанию определяется по домену, на который зашёл браузер |
| `TRUST_PROXY` | `false` | брать IP посетителя из `X-Forwarded-For`; включать только за своим прокси |
| `GEOIP_CITY` | `true` | `false` — только страна, без города |
| `DOMAIN` | — | только установщик: домен для встроенного HTTPS |
| `PROXY_NETWORK` | — | только установщик: docker-сеть прокси |

После правки `.env`: `cd /opt/speedtest && docker compose up -d`. `DOMAIN` и `PROXY_NETWORK`
меняйте через установщик: он пересоздаёт `docker-compose.yml` под нужный режим.

## Если что-то не так

| Симптом | Причина |
|---|---|
| IP вида `172.x.x.x` и «Локальная сеть» | вы заходите из той же сети, что и сервер; снаружи будет реальный IP. Если и снаружи — не включён `TRUST_PROXY` |
| «Потери: н/д» | UDP-порт `RTC_UDP_PORT` закрыт файрволом или не проброшен |
| «Пинг: н/д, WebSocket недоступен» | в прокси не включена поддержка WebSocket |
| «Тест прерван: HTTP 413» | на прокси не задан `client_max_body_size 0` |
| Скорость ниже ожидаемой, в «Подробно → Протокол» указано HTTP/2 или HTTP/3 | на прокси включён HTTP/2: все потоки идут через одно соединение; выключите HTTP/2 для этого сайта |
| Страна и провайдер — «база загружается…» | первые минуты после установки: качаются базы GeoIP |

## Запуск из исходников

```bash
git clone https://github.com/tovich/speedtest && cd speedtest
cp .env.example .env     # по желанию: название, город сервера
docker compose up -d --build
```

HTTPS через Caddy в этом режиме:
`DOMAIN=speed.example.com TRUST_PROXY=true docker compose --profile tls up -d --build`.
Порт 8080 тогда стоит закрыть файрволом: при `TRUST_PROXY=true` прямой доступ к нему позволяет подставить чужой IP.

Без Docker: `DATA_DIR=./data go run .` (Go 1.24+). Для разработки также доступны
`LISTEN_ADDR` (по умолчанию `:8080`) и `DATA_DIR` (по умолчанию `/data`).

## Устройство

```
браузер ──HTTP GET  /api/info            ──▶ IP + DB-IP (страна, город, ASN)
        ──WS        /api/ws              ──▶ эхо (пинг, пинг под нагрузкой)
        ──HTTP POST /api/rtc  (SDP)      ──▶ pion/webrtc, ICE-lite, один UDP-порт
        ◀═UDP DataChannel (эхо) ═════════▶
        ──HTTP GET  /api/download?size=N ──▶ поток случайных байт из памяти
        ──HTTP POST /api/upload          ──▶ чтение и отбрасывание
```

- `main.go` — HTTP-сервер, загрузка и отдача, определение IP, статика (в памяти, заранее сжата gzip).
- `geoip.go` — скачивание баз DB-IP при старте, ежемесячное обновление без перезапуска.
- `realtime.go` — WebSocket-эхо и WebRTC-эхо для теста потерь.
- `web/` — страница; встраивается в бинарник (`go:embed`).
- `install.sh` — установщик; `.github/workflows/docker.yml` — сборка образа.

Базы DB-IP Lite занимают на диске около 135 МБ (город + ASN; скачивается ~65 МБ) и хранятся
в docker-томе. Названия городов в бесплатной базе только на английском; страна выводится
по-русски средствами браузера.

Геоданные: [IP Geolocation by DB-IP](https://db-ip.com), лицензия CC BY 4.0 — ссылка в подвале страницы обязательна.
